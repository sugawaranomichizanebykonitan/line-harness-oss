## 使える土台 (すでに実装済み・本番未使用)

イベント予約機能が丸ごと揃っており、本番のレコード数は0。**WAHMSの講義に
そのまま流用できる**。既存データを壊さずに作り込める。

| 既存テーブル | WAHMSでの意味 |
| --- | --- |
| `events` | 学校 (マーケティング学校 など7校) |
| `event_slots` | 各回の開催日時 (starts_at / ends_at) |
| `event_bookings` | 申込。status に `attended` があり実参加も扱える |
| `event_booking_reminders` | リマインド予約と送信済み管理 |

付随して次も実装済み。

- 申込用のLIFF画面 (`apps/worker/src/client/event-booking`)
- 管理画面 (`apps/web/src/app/events`)
- cronによるリマインド送信 (前日18:00 JST + 指定時間前)
- 自動応答 (`auto-replies`)、リッチメニュー管理、フォーム、シナリオ配信

## 移行の順番

LINEの応答を一度も止めないため、機能ごとに切り替える。GASとWorkerが同時に
返信すると受講者に二重で届くので、**1機能ずつ、GAS側を止めてからWorkerを有効化**する。

| 段階 | 内容 | GASを止める範囲 |
| --- | --- | --- |
| 0 | GASコードとスプレッドシートを読む。機能の棚卸し | なし |
| 1 | 過去分(8/20以降)をD1へ取り込み、画面を現在に追いつかせる ✅**完了 2026-08-25** | なし |
| 2 | 学校6校と今後の開催日をイベントとして登録 ✅**完了 2026-08-25** | なし |
| 3 | 申込をWorkerが記録して返信する ✅**完了 2026-08-25** | 申込のみ (自動) |
| 4 | リマインドをWorkerのcronへ ✅**完了 2026-08-25** | リマインドのみ (自動) |
| 5 | 講義アンケートをWorkerへ ✅**完了 2026-08-25** | アンケートのみ |
| 6 | GASを停止。スプレッドシートは読み取り専用の保管庫にする | 全部 |

段階1と2は既存の運用に一切触れないので先に進められる。

## 移行後に必ず要るもの

### 段階1: 取り込み漏れの補完

| 申込 | 546 | 555 |

申込のうち `TEST_USER_` で始まる2行は取り込んでいない。

### 段階2: 開催予定の登録

GASの `SCHOOLS` 定義 (120エントリ、2026/05/12〜2026/11/11) を
`events` 6件 + `event_slots` 120件として登録した。日付・回・テーマ・時刻を
すべて持っている。

`is_published = 0`、リマインドも無効のまま入れてある。GASと二重に案内が
出ないようにするため。段階3・4で切り替える。

管理画面の「本日」欄と配信先の選択は、この開催予定を見るようにした。
申込が0件の日でも時間とテーマが出る。

### 段階3〜5: 申込・リマインド・アンケート

Apps Script のコードは1行も触っていない。Worker が webhook を先に受け取る
ことを使い、**Worker が確実に扱えたイベントだけ転送を止める**形で引き取った。
GAS側の設定変更もトリガー停止も要らず、いつでもコードだけで戻せる。

#### 申込 (段階3)

`webhook.ts` が「◯月◯日◯◯学校に申し込む」を受けたとき、次を全部満たす場合だけ
Worker が記録して返信し、Apps Script へ転送しない。

- 初回アンケート済み (初参加の人には Apps Script が案内を出す導線がある)
- `event_slots` に今日以降のその回がある (終了済みの案内は Apps Script が出す)
- Zoom の接続情報が `account_settings` にある

**転送するかどうかは返信の成否そのもの**で判定する。Worker が返せなかったら
転送されるので、こちらの不具合が「申し込んだのに無反応」になることがない。

記録先は `wahms_applications` と `event_bookings` の両方。前者は今の管理画面が
見ているところ、後者が移行先。

#### リマインド (段階4)

毎分の cron から `sendWahmsReminders`。開催日の朝7時と開始30分前の2回で、
文面は Apps Script と同一。

**対象は `source_row IS NULL` の申込だけ**。スプレッドシート由来の行には行番号が
入っており、そちらは従来どおり Apps Script が送る。この境目を外すと2通届く。

#### 講義アンケート (段階5)

受講者ごとに使い捨ての案内トークンを発行し (`wahms_survey_invites`)、
`https://wahms.pages.dev/survey?t=<token>` を配信する。

Apps Script の LIFF を使わなくなったので、講義名が「読み込み中」で保存される
不具合が構造的に起きない。回答者も確定するため、質問への1対1返信もそのまま
使える (Web回答は返信できないという制約が、LINE配信ぶんには付かない)。

URLに載るのはトークンだけで、LINEのユーザーIDは出さない。

## 見つかった不具合

- **LIFF講義アンケートが講義名を保存できていない**。8/20以降の回答5件すべてが
  `🎓 講義_読み込み中...` で記録されていた。画面の読み込み完了前に送信される。
  取り込み時に開催日から復元し、`memo` にその旨を残した。**GAS側は未修正**。
- **アーカイブが両系統で分岐している**。管理画面から登録した3件はD1のみ、
  セールス第12回はシートのみに存在した。取り込みで揃えた。

- **開催枠の日付を「今日に一番近い回」で引いていた**。配信から数日後に回答
  されると別の回の集計へ入る。本番で実際に 8/21 の回答が 8/28 として保存され、
  修正済み。案内トークンに書かれた講義で確定するようにした。

## セキュリティ

GASのコードに LINE チャネルアクセストークンと Zoom のパスワードが平文で
書かれている。スクリプトの編集権限を持つ全員が公式アカウントとして配信できる。

Zoom の接続情報は `account_settings` (`wahms_zoom_url` / `wahms_zoom_id` /
`wahms_zoom_password`) へ移し、Worker はそちらを見る。**GAS側の直書きは
残ったまま**なので、GASを止めるときに消すこと。チャネルアクセストークンも同様。
