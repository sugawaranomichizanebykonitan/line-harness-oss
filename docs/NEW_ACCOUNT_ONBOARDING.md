# 新しいLINE公式アカウントを追加する

支援先の企業ごとにアカウントを足す手順。管理画面の左上で切り替えて運用する。
既存アカウント (Frei / WAHMS) のデータとは完全に分離される。

## 1. 先方からもらう情報

### 必須 (これだけで追加できる)

LINE Developers Console → 対象の **Messaging API チャネル** から。

| 項目 | どこにあるか |
| --- | --- |
| チャネルID | 「チャネル基本設定」 |
| チャネルシークレット | 「チャネル基本設定」 |
| チャネルアクセストークン (長期) | 「Messaging API設定」の下部。未発行なら発行してもらう |
| アカウント名 | こちらで決めてよい。管理画面の表示名 |

**シークレットとトークンはチャットやメールに貼らない。** パスワード管理ツールか、
一時的な共有リンクで受け取る。受け取ったら `~/.line-harness/` 配下に置く。

### 機能を使うときだけ必要

| 使いたい機能 | 追加でもらうもの |
| --- | --- |
| LINE内で開くフォーム・診断・予約画面 (LIFF) | LINEログインチャネルのID / シークレット、LIFF ID |
| 無料相談の予約 (Google Meet付き) | 担当者のGoogleアカウント。管理画面から接続してもらう |
| Zoom開催の案内 | Zoom URL / ミーティングID / パスコード |
| リッチメニュー | 画像 (2500x1686 または 2500x843)、タップ領域の割り当て |
| 既存データの移行 | 顧客リスト等のスプレッドシート / CSV |

LIFF が要るかどうかは「LINEアプリの中で画面を開かせたいか」で決まる。
外部ブラウザで開く普通のWebフォームで足りるなら不要
(WAHMSの講義アンケートは、LIFFをやめて普通のWebフォームにした)。

## 2. 先方にやってもらう設定

LINE Official Account Manager と Developers Console 側の作業。

1. **Webhook URL** を次に設定し、「Webhookの利用」をONにする。

   ```text
   https://frei-career.frei-career-consulting.workers.dev/webhook
   ```

   URLはアカウントごとに変わらない。署名から自動で判別している。

2. **応答メッセージをOFF** にする。ONのままだと定型文が先に返り、
   こちらの応答と二重になる。
3. あいさつメッセージは、こちらで作るなら OFF。

## 3. こちらの作業

管理画面 → アカウント → 「+ アカウント追加」。必須4項目を入れれば登録できる。
登録時に、既存の友だちを取り込めるアカウントかどうかも自動で判定される。

先方の担当者に管理画面を触ってもらうなら、**そのアカウントだけ見えるスタッフ**を
作る (`docs/STAFF_ACCOUNT_SCOPE.md`)。他社のデータには一切アクセスできない。

## 3.5 すでに別のツールが入っているアカウント (Lステップ等)

**LINE の Webhook URL はアカウントに1つしか設定できない。** すでに Lステップ・
Liny・エルメ等が入っているアカウントは、そのままでは繋げられない。

こちらを**前段**に置き、受け取った生のリクエストをそのまま既存ツールへ渡す。
WAHMS で Apps Script に対してやってきたことと同じ形。

```text
LINE ──▶ Worker ──▶ (無加工で転送) ──▶ 既存ツール（応答はこちらが担当）
              └──▶ D1 に記録（友だち・トーク履歴）
```

`line_accounts` の2列で切り替える。

| forward_mode | 動き | 使いどころ |
| --- | --- | --- |
| `always` | 全イベントを転送し、**こちらからは一切返信しない** | 既存ツールが応答を担当 |
| `fallback` | こちらが応答し、返せなかったときだけ転送 | WAHMS |
| `NULL` | 転送しない | 単独運用 |

`forward_webhook_url` に既存ツールの URL を入れる。

### 落とし穴

- **署名ヘッダ (`X-Line-Signature`) を必ず一緒に渡す。** 本文を1バイトも変えずに
  転送するので、受け取った側の署名検証がそのまま通る。落とすと転送先が全部
  401 になり、相手の運用が止まる。Apps Script は検証していなかったので
  今まで表面化しなかった。
- **replyToken は一度しか使えない。** `always` のときは follow / message /
  postback のいずれでもこちらから返信しない。記録だけで返る。
- **こちらが単一障害点になる。** Worker が落ちると既存ツールにもイベントが
  届かない。引き受ける前に先方へ説明すること。

### 切り替えの手順（元に戻せる形で）

1. **今の Webhook URL を控える**（これが戻し先）
2. `line_accounts` に `forward_webhook_url` と `forward_mode='always'` を入れる
3. LINE 側の Webhook URL をこちらに差し替える
4. **すぐに自分から1通送って確認する**
   - こちらのログに転送成功が出るか
   - 既存ツールの返信がこれまでどおり来るか
5. おかしければ 1 で控えた URL に戻す（10秒で戻る）

## 4. 個人情報を集めるとき

フォームで氏名・連絡先などを集めるなら、先方のプライバシーポリシーに
取得目的と保存先の記載が要る。健康状態・既往歴は**要配慮個人情報**にあたり、
取得に明示的な同意が必要になる。設問を決める前に先方の法務確認を挟む。

保存先は D1 (Cloudflare)。バックアップは `~/Desktop/line-harness-backups/`
に置き、Git には絶対に入れない。
